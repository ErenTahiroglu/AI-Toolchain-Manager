# CONFIG-01 — tests and threat model

The commit's own SHA and the exact-SHA CI result are not recorded here; they are in the hand-off reply and in the comment on Issue #30. What follows separates **what was run locally** from **what a pure-function test can and cannot show**.

## Threat model (the preview as built)
| # | Threat | Control in the preview | Residual risk |
|---|---|---|---|
| T1 | The preview is mistaken for permission or for a finished change | `applied: false`, `touchedFiles: 0` constants; "ÖNİZLEME — UYGULANMADI" and "Hiçbir dosyaya dokunulmadı …" on every result; no apply, save, export, copy or download control exists | A person can still copy text by hand from the page; the masked view is not a usable file |
| T2 | A plausible-looking command is made up | Declarations come only from a reviewed registry; it is empty; no declaration → `BLOCKED_INSUFFICIENT_EVIDENCE`, no diff; publisher commands, README examples, `@latest` and key-in-URL snippets are never templates | The first real entry will need a human review that these tests cannot replace |
| T3 | A reviewed declaration is unsafe anyway (unpinned runner, shell metacharacters, path escape, credential in a URL, literal secret) | `validateDeclaration` re-checks hygiene at run time; a failing entry is not used and the reason is shown | Hygiene is not trust: an exact, pinned package can still be malicious |
| T4 | An existing block is bypassed through the preview | Catalog gates (quarantine, execution policy, removed, disabled, undeclared compatibility, not-an-MCP-entry) produce `BLOCKED_BY_CATALOG`; any diff for such an entry is "hypothetical / not a recipe"; the matrix's accept rules are unchanged and tested | none identified |
| T5 | A wrong file is previewed (Claude Desktop, CLI, another Antigravity interface, a settings file, `CLAUDE.md`, a global file) | Surface → host is a two-row table; every other surface is `UNSUPPORTED_SURFACE`; paths are constants; user-global files are listed as untouched | The Antigravity IDE path rests on one sentence of a summarised page |
| T6 | Secrets in the pasted text reach the screen, a log, a test output or a stored place | Values are parsed, redacted and re-serialised before display; engine error messages are never shown; only a SHA-256 of the pasted text is kept; no storage, clipboard, network or log | Redaction is pattern-based: an unusual secret shape could survive; the UI tells the user not to paste secrets |
| T7 | Silent data loss or overwrite in the proposal | Duplicate keys, wrong types, same-name and equivalent servers are refused; unrelated keys and servers are preserved in order; the display is re-formatted and says so | Key order of integer-like keys is normalised by the JavaScript engine; irrelevant for MCP files, noted |
| T8 | A stale preview is acted on | `inputKey` covers every input; a differing key hides the result | Staleness protects the *screen*; a future write needs the real-file digest check (see `FUTURE_WRITE_GATE.md`) |
| T9 | Hostile pasted text (huge, deeply nested, prototype keys) | 200 000-character cap, 200-server cap, own-property handling of `__proto__` | Very deep nesting is bounded only by the engine's own limits (a stack error would surface as a generic failure, not a leak) |
| T10 | The preview opens a path to real writes | No Rust change, no IPC command, no capability, no dependency, no file API in the sources (tests pin all of it); the future write is specified, not implemented | Issue #14 (real write/cleanup) and #25 (WebView2) are untouched and open |
| T11 | Headless runs load project servers without asking (documented Claude Code behaviour) | stated in every Claude plan's constraints | A reader may skip it |

## What the tests cover
**Pure planner (`src/configPlan.test.ts`, 40 tests):** exactly two hosts with fixed relative paths; every other surface (Desktop, command line, other Antigravity interfaces, wrong case, empty) is `UNSUPPORTED_SURFACE`; the path does not depend on OS or project; identity is never defaulted (`INVALID_INPUT` for empty alias, entry or an unknown OS); the shipped registry is empty and every host × OS × mode gets `BLOCKED_INSUFFICIENT_EVIDENCE` with no stanza; a non-MCP entry; a declaration of another entry or host is not used; new file and existing file previews preserve unrelated keys, servers and their order and add exactly one stanza; a file with no `mcpServers`; Antigravity; formatting normalisation and BOM; malformed JSON, comments, trailing commas, empty and non-object content; the engine message is never shown; duplicate keys at any depth (and not for equal values or the same key in different objects); wrong structural types; size caps; same-name and equivalent-server conflicts; a deeper key named `mcpServers`; prototype-style keys; secret masking (keys, flags and their next argument, URL credentials, queries and fragments, token shapes, long opaque strings) with none of the sentinels in any status; `${NAME}` references kept; quarantined, execution-blocked, undeclared/unsupported compatibility, removed and disabled entries; hygiene rules for declarations (unpinned runners, dist-tags, shell metacharacters, absolute and traversal paths, unknown fields, non-https or credential-carrying URLs, literal env/header secrets, Antigravity without env/headers, bad names, host mismatch, malformed review records) and the refusal to use a failing entry; determinism; staleness on every input; SHA-256 against published vectors and, over every length 0–200 plus non-ASCII text, against the platform's WebCrypto; the line diff.
**Component and matrix row (`src/ConfigPreview.test.tsx`, 21 tests):** nothing for non-MCP entries; closed by default, no mode chosen, one button, no apply/save/copy/download; refusal with guidance and focus when no mode is chosen; a new-file preview with identity, path, scope, before/after, focused diff and the no-file-touched statement; the result takes focus; keyboard-only use; existing-file preview; secrets never on screen (also in the broken-file path); malformed, commented, duplicate and mistyped text refused with plain reasons; same-name conflict; stale results withdrawn on text, mode and target change; the shipped (empty) registry; quarantined entries as explanatory only; unknown compatibility; unsupported surfaces; Antigravity IDE path and untouched global file; no IPC call, clipboard, fetch or storage during a whole session; the new sources contain no I/O access; the Tauri capability grants no filesystem, shell, HTTP, dialog, clipboard or configuration permission; in the real matrix row only the MCP entry has the control, it opens blocked, writes no wish, and every IPC call made is a read.
**Python (`tests/test_config01_contract.py`, 7 tests):** empty registry; the two host files and surfaces; capability file; no Rust configuration command; pure sources; the documents state the boundaries; the publisher sources are registered.
**Existing tests:** unchanged. The matrix, decision, observation, review-queue and catalog suites pass as before; the one existing type (`ToolRecord`) gained an optional `category` field.

## Mutation checks (one change at a time, SHA-256-verified restore) — 15 of 15 caught
Wrong Claude path; Desktop mapped onto the Claude file; secret keys no longer masked; duplicate keys not detected; same-name server overwritten; a declaration used for any entry; catalog blocks ignored; staleness ignoring the pasted text; the plan claiming to be applied; unpinned tags accepted; the control shown for non-MCP entries; a mode preselected; the engine message shown; the "before" view unmasked; the proposal dropping unrelated keys. Thin spots: "a declaration used for any entry" and "unpinned tags accepted" are each killed by a single test.

## Not tested / limits
* A real window, screen reader, keyboard hardware, high zoom, dark theme and editorial review of the Turkish (jsdom and `user-event` only).
* Real files: nothing was read or written, so symlink, junction, hard-link, encoding, line-ending, permission and concurrency behaviour is **unverified by design** and is the subject of `FUTURE_WRITE_GATE.md`.
* The publisher documentation was read through a summarising tool; the Claude MCP page only up to ~100 000 of ~150 000 characters; the Antigravity IDE path rests on one sentence.
* No reviewed declaration exists, so the *positive* path is exercised only with synthetic registries; the application itself always answers "blocked" today.
* The Windows GUI harness `tools/gui_jq_pilot_locked.mjs` (not run, Phase 3D tooling, untouched) is unaffected.
