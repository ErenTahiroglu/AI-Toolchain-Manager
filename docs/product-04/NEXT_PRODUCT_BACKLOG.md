# PRODUCT-04 — next product milestones (proposal; replaces the PRODUCT-03 list)

Done by PRODUCT-04: the Project Tool Workspace shows, per row and apart from the wish, the last **stored** discovery observation of an accepted wish (exact four-field key, backend status unchanged, honest loading/error/old states, no scan). Still **not** proposed: real installation, the jq pilot, any change to pilot gates or Smart App Control handling, the deferred offline-preflight harness, signing / auto-update, cloud sync. Real installation stays behind its own acceptance gate (Issues #14 and #25 open, independent Red Team, separate explicit instruction). No secrets or private paths belong in this file.

| # | Milestone | Measurable user value | Prerequisites (state today) |
|---|---|---|---|
| 1 | **Review queue.** One list of decisions with `materialChange`, postponed wishes past their reminder date, wishes on removed catalog entries, and accepted wishes whose stored observation is `previously_*` / `platform_mismatch` / `not_scanned`, with a Dashboard count tile. | The count reaches 0 after review; the user knows what to look at first. | All fields exist (preferences + `Inventory.requests`). Frontend + one tile; no background process, no scan. |
| 2 | **Evaluation-log hygiene (needs Rust, so its own phase).** A UI-discarded evaluation must not consume the "already shown for this task" slot, or expose a read-only dry-run evaluation. | No suggestion is "used up" by an answer nobody saw; the UI workaround (fresh task id) can go. | Change in `recommend.rs` / `commands.rs`: outside the frontend-only phases. |
| 3 | **Observation provenance in the contract (needs Rust).** Let `RequestVsObservation` say whether the status rests on a project-specific, computer-wide or `local-cli` observation, and carry the age of the evidence. | The matrix can stop saying "may count for every project" and say which it is. | Small additive field in `store.rs`; TypeScript type + one line of UI. |
| 4 | **Per-project plan export (read-only).** Markdown/JSON "desired toolchain" that says *wish* and *last stored observation* separately and never says "installed". | A plan can be handed to a teammate. | First user-driven file write: typed command, user-chosen location, security review. |
| 5 | **Transparent suggestion overlay (only after the rule set is audited).** Show the deterministic rule result for a task typed on Recommendations as a mark on matrix rows, kept in the typed handoff, no new storage. | From a task description to the relevant undecided tools without a second screen. | The rule set has **not** been audited; do not build before that. |
| 6 | **Hygiene bundle.** README status banner ("Phase 3D-0"); Turkish copy review of the new observation text; fold the Plan page's target selection into the shared helper; an `AbortController`-style convention for new async flows. | No stale phase claim on the first README screen; reviewed copy. | None. Small and safe. |

## Order and why
1 builds directly on what PRODUCT-04 added and is frontend-only. 2 and 3 are Rust changes and should be separate, reviewed phases; 2 should precede anything that evaluates more often than the user clicks. 4 introduces the first write path of its kind. 5 waits for the rule audit.
