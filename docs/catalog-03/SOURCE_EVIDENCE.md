## What each source says, and what it does not

### Understand Anything (R41)
* **Is:** a Claude Code plugin ("multi-agent pipeline") that scans a project and builds a knowledge graph of files, functions, classes and dependencies, saved to `.ua/knowledge-graph.json` (the legacy `.understand-anything/` folder keeps being used when present), with an interactive dashboard and further commands (chat, diff, explain, onboard, domain).
* **Cost and data:** the README warns the first analysis "can consume a significant number of tokens on large projects" and suggests a subscription plan or a local model; the analysis is done by the host agent, so what leaves the machine depends on the host's provider. Later runs are incremental.
* **State written:** the graph and metadata under `.ua/` (the publisher suggests committing everything except scratch files); `hooks/hooks.json` defines a PostToolUse hook (matcher Bash) running a Node script and a SessionStart hook that checks staleness and tells the agent to read an update prompt and follow it. An auto-update mode patches the graph after commits.
* **Local server:** the dashboard is served on `127.0.0.1` with a token in the URL; a stand-alone viewer (Node 18 or newer) is fetched from a GitHub release URL.
* **Installers:** Claude Code is the "native" route (marketplace commands). For fourteen other platforms — Codex, OpenCode, OpenClaw, **Antigravity**, Gemini CLI, Pi, Vibe, VS Code Copilot, Hermes, Cline, KIMI, Trae, Nanobot, Kiro — there are **one-line installers that pipe a remote script into a shell**: `bash` for macOS/Linux and PowerShell `iex` for Windows. They clone the repository to a folder under the user's home and create links. These were read and are **forbidden here**; the record says "pipe-to-shell" and never contains the command.
* **Not stated:** any operating system for the Claude Code route; which Antigravity surface (IDE, CLI, Antigravity 2); any telemetry policy.

### Claude-Mem (R42)
* **Is:** "memory compression system for Claude Code": lifecycle hooks (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, SessionEnd) capture tool use; a local worker service (managed by Bun), a SQLite database and a Chroma vector index store and search it; settings live in `~/.claude-mem/settings.json`.
* **Where data can go:** the installer asks the user to sign in (email magic link) and then to pick a memory provider — the publisher's hosted **observer** (30-day free trial), the user's own OpenRouter or Gemini key, or the Anthropic plan. For the Grok Bot integration the README says the default is "CMEM Pro, the hosted memory"; there is optional **cloud sync** ("back up your memories to cmem.ai"); and the marketplace's second plugin (`claude-mem-cowork`) is described as streaming tool use to cmem.ai. A `<private>` tag excludes content from storage. This record **does not extrapolate** the Grok Bot default to other clients, and it does not claim that local-only operation is the default or the only mode.
* **System effects:** `npx claude-mem install` places a launcher in the user's local application-data folder and adds it to the user Path (Windows section), and Bun and uv are "auto-installed if missing".
* **Platforms:** Claude Code (plugin marketplace route and installer), OpenCode, T3 Code, Antigravity **CLI**, OMP, Pi, DeepSeek Harness, OpenClaw (pipe-to-shell), Cursor, Grok. Only a **Windows** setup section exists for Claude Code hooks; no macOS section.
* **Discrepancy:** `package.json` says Node `>=20.12.0`; the README says "20.0.0 or higher". Recorded as not reconciled.
* **Also in the README:** a section about "CMEM", a token created by a third party and "officially embraced" by the author. Not evaluated and irrelevant to the catalog entry. The repository root also holds a file whose name mentions an analytics product; it was not opened, so telemetry stays `unknown`.

### The Karpathy-inspired repository (R43)
* **Is:** the complete tree is nine files: a root `CLAUDE.md` (four principles: think before coding, simplicity first, surgical changes, goal-driven execution), `CURSOR.md`, `EXAMPLES.md`, two READMEs, a Cursor rule, two plugin manifests and one skill (`skills/karpathy-guidelines/SKILL.md`). No code, script or hook exists in the pinned tree. `skill_collection` was chosen because the entry distributes an instructions-only skill (not an executable, hooks or an MCP server, which is what `agent_plugin` implies in this catalog), with the single skill exposed through a plugin manifest.
* **Identity:** the canonical repository is `multica-ai/andrej-karpathy-skills` (the first lines of the README promote a different project of that owner). The README, both manifests and the skill-install commands **still name `forrestchang`** as author, owner and source. They are historical or stale; this catalog does not source anything from that account, and the record's identity fields contain only the canonical owner. The README describes the text as derived from public remarks of Andrej Karpathy; the repository is a third-party work and neither authored nor endorsed by him (the summary says "Karpathy’den esinlenmiş, üçüncü taraf").
* **Licence:** MIT is *stated* in three places, but no licence file exists and GitHub detects none, and no copyright holder is named, so there is no independently reviewable grant. `license.state = review-required`, `spdxId = null`, `evidenceId = null`. No SPDX identifier is asserted to pass the quality gate (see the documented exception).
* **Install text:** a plugin route (marketplace under the former owner) and a route that downloads `CLAUDE.md` from the former owner's repository into a project file (or appends it to an existing one). Neither is an approved method; this application never writes `CLAUDE.md`, `AGENTS.md`, `.claude/` or any project instruction.

### Ruflo (R44)
* **Is:** "an agent meta-harness for Claude Code and Codex" (originally Claude Flow): swarms, hooks, a daemon, 12 background workers, vector memory, multi-provider routing (Claude, GPT, Gemini, Cohere, Ollama) and optional cross-machine **federation** over secure websockets. The marketplace manifest lists **47 separate plugin modules** (core, console, mods, swarm, autopilot, loop workers, browser, security, federation, and more).
* **Workspace effects:** the README's comparison table says the CLI route (`init`) writes `.claude/`, `.claude-flow/`, `CLAUDE.md`, helpers and settings and installs hooks and the daemon, while the plugin route writes "zero" workspace files.
* **Packaging ambiguity:** the root `package.json` is named `claude-flow` (bin `claude-flow`), the plugin manifest is a stale `claude-flow` 2.5.0 pointing at another repository, with `alpha`/`latest` npm tags and a cloud MCP server that "requires authentication", and the README offers `npx ruflo` and `npm install -g ruflo`. Nothing in the pinned files establishes that the `ruflo` package of the README is the same artifact as the root manifest, so **no approved install method and no platform statement is derived from it**.
* **Platforms:** the README says a `npx` init works "on all platforms (including native Windows PowerShell / cmd)" and shows a POSIX-only pipe-to-shell installer; no Antigravity mention. Because that path's package identity is unverified, it is **not** taken as an operating-system declaration.
* **Not stated:** any telemetry policy.

## How the compatibility labels were chosen
Rule (the same as CATALOG-01/02): `vendor-declared` only when the publisher's own text names **both** the exact agent surface **and** the operating system family for the same route; no source names a CPU architecture; Linux-only or pipe-to-shell instructions never count; anything else is `unknown`. Six cells per entry (Windows x64 / macOS arm64 × `local-cli` / `claude-code-terminal` / `antigravity-ide`), each with its limitation.

| | `local-cli` | `claude-code-terminal` | `antigravity-ide` |
|---|---|---|---|
| **Understand Anything** | unknown (a viewer only; no OS named for it) | unknown (native plugin route; OS appears only for the other platforms' installers) | unknown ("Antigravity" without a surface, via a pipe-to-shell installer) |
| **Claude-Mem** | unknown (the launcher is for hooks) | **Windows: vendor-declared** (Windows setup section for Claude Code hooks); macOS: unknown | unknown (Antigravity **CLI** documented, which this application does not offer as a surface) |
| **Karpathy-inspired** | unknown (plain text) | unknown (no OS named; routes point at the former owner) | unknown (Claude Code and Cursor only) |
| **Ruflo** | unknown (identity of the CLI package unverified) | unknown (the "all platforms" route has an unverified package identity; quarantined) | unknown (no mention) |

The single declared cell is on a **quarantined** entry that is blocked-until-scoped-authorization, so it can never permit "kullanmak istiyorum"; a test pins that.
