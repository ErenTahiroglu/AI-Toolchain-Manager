# Phase 0 Independent Red Team Review

**Scope:** Architecture and public product/source documentation only, snapshot 2026-10-10. The application does not exist, so there are no implementation vulnerabilities to confirm. This is a source-informed design attack review, not a penetration test, independent human sign-off, installer audit, or guarantee of correctness. All nine tools were not executed.

## Findings

| ID | Priority | Attack/failure path | Design disposition / evidence needed |
| --- | --- | --- | --- |
| RT-01 | Critical design blocker | A user pastes a GitHub URL; a README, manifest, workflow, or installer script contains hostile instructions; an agent follows them or the app executes the script. This crosses from untrusted repository data to user-level code execution. | Static inspection only in discovery; no shell. Tainted content shown as data. Unknown recipes are manual-only. Before any installer adapter, test command allowlist, path confinement, network policy, and sandbox on both OSes. |
| RT-02 | Critical design blocker | The manager appends/replaces `CLAUDE.md`, `GEMINI.md`, agent JSON, or hook config; it erases user rules, injects a malicious MCP endpoint, exposes a token, or silently changes behavior. | Structural parse and diff preview, ownership markers, exact backups, read-after-write verification, conflict refusal; tests with comments/JSONC, symlinked files, duplicate markers, and user-edited blocks. Never overwrite whole file. |
| RT-03 | Critical privacy risk | Gitleaks/Betterleaks matches a real credential and raw stdout, exception, event log, bug report, or private sync serializes it. A credential validator can also transmit a token to a provider. | Use synthetic fixtures; redact before every boundary; no raw output logs; scanner validators/revocation are distinct explicit capabilities, default off; inspect exports. A no-finding result is not proof no secrets exist. |
| RT-04 | High | Tool or app update swaps binary/configuration while Claude/Antigravity has an active session, corrupting a running process/config or causing session failure. | Per-adapter process/session check; hold write lock; stage and verify first. Unknown session status blocks mutation. If the user closes sessions manually, require explicit acknowledgement and verify process absence before write. |
| RT-05 | High | A mutable default branch/tag or compromised release serves different code after review; adjacent checksum is replaced with the malicious artifact. | Pin exact immutable commit and signed release/manifest; independently verify key fingerprint and signature chain. Reject floating refs, same-origin checksum-only confidence, and mismatched provenance. |
| RT-06 | High | Caveman's profile is selected but its CLI is also installed; default-on telemetry, local prompt/recovery database, or proxy behavior is inadvertently activated. | Separate components/capabilities, opt-out verified at the background process, profile-only installs, egress inventory and separate consent. Current Caveman docs identify content-free telemetry plus IP/install/session/token aggregates and local recoverable payload stores. |
| RT-07 | High | Private preference sync sends machine path, private repo URL, profile or project identifier, logs, or credentials; concurrent devices overwrite a newer/different response policy. | Strict sync allowlist, manual neutral alias pairing, optimistic concurrency, surfaced non-commutative conflicts, no LWW for security/profile settings, local-only paths/state, token in OS credential store. Round-trip and conflict tests required before enabling. |
| RT-08 | High | Tauri WebView compromise invokes an over-broad filesystem/shell/SQL command; app Rust core carries full user privileges. | No generic shell IPC; capabilities least-privilege, strict CSP, typed/validated commands, command-level scope checks, safe URL opener, adversarial IPC tests. Tauri's security docs explicitly distinguish privileged Rust core from restricted WebView. |
| RT-09 | High | Green status is derived from install success or a tool's self-report while wrong binary, wrong version, disconnected MCP, broken hooks, stale graph, or no-op behavior persists. | Separate presence/version/protocol/functional checks; independent harness; report unknown/stale; failure injection; never let AI or installer set verified. |
| RT-10 | Medium | Two graph or secret tools are simultaneously enabled; duplicate hooks add context, compete over indexes, generate duplicate false-positive reports, or leak output to model context. | Tool relationship/collision detection and per-project activation queue. Offer one graph tool and one secrets scanner initially; only permit combination with explicit reason/test. |
| RT-11 | Medium | ASD-STE100 wording is packaged/reproduced or marketed as officially compliant/certified. | Original general guidance only. The specification is free to obtain but copyright/trademark owned by ASD; owner says it does not certify/authorize commercial “fully compliant” products. Seek written permission/legal review for substantive reproduction/checker. |
| RT-12 | Medium | Local event hash chain is presented as a tamper-proof audit trail even though the same OS user can rewrite both records and hashes. | Call it integrity/tamper-evidence for accidental edits only; restrictive ACL, immutable/exported signed chain head optional, disclose same-user rewrite limitation. |
| RT-13 | Medium | “Offline” status looks healthy because cached record says installed; tool is missing/broken, signature revocation unknown, update catalog stale, or health check cannot run. | Make freshness timestamp and offline limitations visible. Keep last-known verified state distinct from present health. No update/install in offline mode; local functional check only. |

## Attack Scenarios to Preserve as Tests

- README prompt injection, URL redirect to non-GitHub host, encoded traversal, submodule pointer, malicious archive path, poisoned JSONC/YAML and oversized manifest.
- Installer script tries shell expansion, writes outside managed root, reads process environment, follows symlink, or changes a second agent's global config.
- Truncated artifact, valid adjacent checksum but bad signature, wrong signer, tag moved, hash collision/mismatch, archive path escape, interrupted atomic swap, active process lock, rollback after SQLite migration.
- Scan output contains dummy token in error/telemetry/UI; real secret would be excluded. OAuth token in URL, headers, environment, command args, crash dump, conflict report, or sync event is rejected/redacted.
- User modifies manager block while app is closed; another tool rewrites file format; app detects conflict and refuses. Reject/disable/remove/uninstall must have different effects.
- Sync same project profile changes from two devices with concurrent sequence numbers, old schema, replayed event, expired token, offline queue, and stale snapshot.
- Mac app signature/notarization failure, Windows Authenticode/SmartScreen warning, WebView2 unavailable, startup disabled by policy, tray unsupported or removed, single-instance callback failure, corrupt local SQLite and full disk.

## Verdict Boundaries

- No confirmed application vulnerability: no application code exists.
- Confirmed design-level unacceptable default: executing unverified installer content would be unsafe and violates the requirements. Architecture prohibits it.
- Third-party features such as checksums, telemetry opt-outs, host approval prompts, and rollback are publisher/version-specific and require validation at the exact pinned release.
- A successful deterministic suite raises evidence confidence for named paths only; it does not imply full product correctness, safety of model-generated instructions, or absence of undiscovered vulnerabilities.

## Independent Review Needed

Before public app release, a reviewer who did not author the implementation must inspect the threat model, Tauri permission/capability manifest, GitHub fetcher and URL validation, installer adapters, config-preservation implementation, redaction tests, sync allowlist, update signing/key recovery, and failure-injection results. This Phase 0 document review is not that later implementation review.
