## Threats and controls
| # | Threat | Control | Residual |
|---|---|---|---|
| T1 | A pasted `success` / `accepted` / `verified` is read as real | Closed vocabularies; the view-model has **no** verdict member (a test walks every key at every depth); constant trust label on the page and on every record; "bildirilen" before each claim; "(denetlenmedi)" after each job conclusion; reviewer claim states it is not an independent approval | A person can still *choose* to believe a claim; the page cannot prevent that |
| T2 | Forged identity (wrong repo, wrong/truncated/uppercase commit, wrong run/attempt) looks plausible | Strict syntax (40/64 lowercase hex, `owner/repo` grammar, positive bounded integers), cross-record identity rules (same run id under two repo/commit pairs, duplicate run+attempt, duplicate records) | **Syntax is not existence**: a perfectly formed fake commit is accepted as a *claim*; nothing is checked remotely, by design |
| T3 | An old accepted commit is read as applying to the current branch | Fixed scope sentence on every record (no branch-head check); `branch_head_not_checked` is a first-class missing-evidence value; no wording says "latest/current" | The user may still misread an old record |
| T4 | Active content: HTML/script/Markdown, `javascript:`/`data:` URLs, links, event handlers, template syntax | Character allow-list for free text (no `< > [ ] { } \ / @ $ % & = ? ! * \| ~ ^ " \``), URL/scheme pattern rejection, React text rendering only, **no** `<a>`, `href`, `dangerouslySetInnerHTML`, `innerHTML` anywhere in the application (source scan in two suites) | – |
| T5 | Secrets or private data pasted (tokens, keys, long hex, paths) | Secret-shaped patterns and secret words rejected (a field that cannot be policed is **refused, not redacted**); local-path characters not allowed; errors never echo input; nothing stored or exported | A secret that matches no pattern and passes the allow-list (e.g. an ordinary-looking short phrase) would be shown on screen; it stays in memory only and is destroyed on leaving the page |
| T6 | Resource exhaustion: huge text, deep nesting, huge numbers, many values/records | 40 000-character cap checked first; a tolerant raw scanner rejects depth > 8, > 3 000 values, and non-plain-integer numbers **before** `JSON.parse`; per-list caps | – |
| T7 | Ambiguity: duplicate JSON keys (also escaped spellings), prototype-style keys | Raw scanner decodes keys and rejects repeats; unknown keys (including `__proto__`, `constructor`) are `unexpected_key`; objects must be plain | – |
| T8 | Error messages leak or reflect input | Closed error codes + Turkish sentences; the `path` is built only from schema key names and indices; tests feed a sentinel through 12 kinds of failure and assert it never appears | – |
| T9 | Data persists or travels | State lives in one component; the app re-mounts a page per navigation; "Temizle" clears both; editing hides the old result; a failed attempt discards the old result; no IPC/fetch/clipboard/storage/`window.open` (spied at runtime and scanned in source) | The browser's own form/IME/undo buffers, an OS clipboard the user used themselves, and screen sharing are outside the application |
| T10 | Time-based claims read as live facts | `now` is a parameter; the page reads the clock once at "Göster" and prints that instant; expiry is only a comparison of a *declared* timestamp, boundary instant counts as past, with explicit "denetlenmedi" wording | The device clock may be wrong |
| T11 | Scope creep into verification (hash checks, fetching, aggregation, "all green") | No such code exists; `EXTERNAL_ENGINE_HANDOFF.md` forbids it; a contract test pins the view-model's members | A future change could add it; review must catch it |

### What the parser tests cover
Forged conclusions (`PASS`, `VERIFIED`, `ACCEPTED`, case variants) and extra `verified/status/accepted` keys at every level; reviewer claim for another commit; commit/digest forms (uppercase, 39/41/7 chars, non-hex, padded, wrong types); 22 repository forms incl. URL, traversal, whitespace, overlong, case-insensitive duplicate detection; run id / attempt / issue / PR / artifact numbers (0, negative, fraction, exponent, leading zero, 17 digits, beyond 2^53−1, strings, null, duplicates, the limits themselves); inconsistent run identity across repositories and commits, duplicate run+attempt, another attempt of the same run (allowed); failed/skipped/cancelled/missing/extra/duplicate/zero jobs; artifacts absent, retained-but-past-expiry, expired-but-future-expiry, no digest, invalid timestamps, the boundary instant and moving the clock; unknown/missing/mistyped schema versions; unexpected and missing keys at every level; `null`; wrong container types; 17 kinds of malformed JSON; non-string and empty input; size, depth (including 30 000 unclosed brackets and 40 nested objects), value-count and every list/string limit at, and one over, the bound; duplicate keys at the root, nested, and via an escaped spelling; **6 free-text fields × 51 hostile values** (HTML, Markdown, URLs, schemes, paths, tokens of six families, key blocks, hex/opaque runs, secret words, control/bidi/zero-width characters, emoji, NFD text, templates, quotes, shell punctuation) each refused and never echoed, plus ordinary Turkish text accepted unchanged in each field; the `ref` assertion's own syntax; error results never contain input; the module is pure (no clock, IPC, storage, DOM, timer).

### What the page tests cover
Navigation entry and `aria-current`; empty state; empty submit; every field of a valid record (full commit, run id **and** attempt, ref as assertion, claimed jobs with "denetlenmedi", expected jobs, artifact id/digest/expiry/claim, issue/PR numbers as inert text, reviewer claim, limitations, missing evidence); the trust label on the page and on each record; no "current head" claim; no icon/link/image/badge/progress/control and none of the words *doğrulandı/onaylandı/başarıyla/PASSED/VERIFIED*; clock-once wording; heading structure and focus landing on the result; forged records; neutral notes; multiple records without a total; 14 hostile/invalid pastes (HTML, script, Markdown link, `javascript:`, token, secret word, path, unknown version, unexpected/forged key, malformed JSON, run id 0, uppercase commit, oversize) each giving an alert with a closed code, no echo, nothing rendered and no injected element; failed attempt discards the previous result; "Temizle" (text, result, error, focus); editing hides the result; leaving the page (and unmounting) removes every trace; runtime spies show **no IPC call, no `fetch`, no clipboard, no storage write, no `window.open`** across paste/show/fail/clear; source scans; keyboard-only flow (Tab order, Enter, Space, focus on the result and back to the box); accessible names, `role=alert`, polite status; the example record is static, collapsed, with no copy control.

### Mutation checks (one change at a time, SHA-256-verified restore)
**28 of 28 caught** (26 behavioural/UI mutants and 2 contract mutants): uppercase commit and uppercase digest accepted; duplicate JSON keys accepted; unknown schema version accepted; unexpected keys ignored; the trust label dropped from the record card; the reviewer claim losing its "not an approval" wording; data rendered as HTML; secret words no longer refused; the free-text allow-list disabled; editing keeping the old result on screen; "Temizle" not clearing the text; the error path echoing the unexpected key name; run attempt 0 accepted; inconsistent run identity accepted; the expiry boundary instant counted as future; the page persisting the pasted text; the navigation entry removed; the nesting limit removed; a verdict member added to the view-model; duplicate job names accepted; the scope sentence dropped; job conclusions losing "denetlenmedi"; oversized input accepted; exponent/fraction numbers accepted; the page starting to import the IPC layer; a verdict-like member in an interface (contract); a link in the page (contract). No mutant survived. Thin spot: several controls are layered (for example a URL is refused both by the character allow-list and by the scheme patterns), so a single mutant that removes only one layer would not necessarily fail a test aimed at the other; the allow-list mutant (M19) and the secret-word mutant (M8) are caught by the hostile-value matrix, which exercises each layer's own cases.

## Not tested / limits (honest)
* **jsdom only.** No real window, no screen reader, no high-zoom, dark-theme or print check, no real clipboard/IME behaviour; the Turkish copy has had **no editorial review**.
* **Syntax-only trust.** The viewer cannot tell a real commit/run/artifact from a made-up one; that is the external engine's job and it does not exist yet.
* **Free-text policy is conservative:** legitimate sentences containing a secret word (e.g. "token"), a colon directly followed by text, a slash or a quote are refused.
* **Strictness is forward-hostile:** a newer envelope with an extra field is refused as a whole (fail closed); the schema version is the only extension point.
* The local-only intermittent vitest failures seen in `PlaywrightChoice.test.tsx` under load (a pre-existing, timing-sensitive file; a different test of it failed once during this work and passed alone and in the next full run) were **not** modified here.
* Nothing is stored, so there is nothing to test across restarts beyond "the page starts empty and holds no persisted data", which the lifecycle tests and the absence of any storage API cover.
* Green CI is not independent acceptance; the Red Team has not reviewed this change.
