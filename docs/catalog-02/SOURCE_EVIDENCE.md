## What each source says (and what it does not)
**Playwright CLI (R38).** README: "CLI with SKILLS" for coding agents; says CLI invocations are more token-efficient than MCP because they avoid loading large tool schemas and verbose accessibility trees into the model context, and names MCP as the choice for specialised loops that need persistent state. Requirements: Node.js 18 or newer; "Claude Code, GitHub Copilot, or any other coding agent". Install: a global npm install (unpinned `latest`) and an optional skills install step that Claude Code and others then use. Sessions: the browser profile is kept **in memory** by default (cookies and storage survive between CLI calls in the session, lost when the browser closes); a persistent option saves it to disk; named sessions (`-s=`) can separate projects; headless by default. Commands include reading, setting and clearing cookies and storage, saving and loading storage state, evaluating page JavaScript, running Playwright code, request mocking, tracing and video. **Not stated:** any operating system or CPU architecture, any telemetry policy.
**Playwright MCP (R39).** README: MCP server over accessibility snapshots; itself says coding agents "might benefit from using the CLI+SKILLS instead" and that MCP suits stateful exploratory loops, self-healing tests and long-running workflows where continuous browser context outweighs token cost. Requirements: Node.js 18 or newer; per-client configuration sections include **Claude Code** (a `claude mcp add …` command) and **Antigravity** (settings or a configuration file; the surface — IDE, CLI, "Antigravity 2" — is not named). The browser profile is **persistent on disk by default** (locations for Windows, macOS and Linux, separate per workspace); an isolated mode keeps it in memory; an extension mode attaches to an existing logged-in Chrome/Edge. Options include origin allow/block lists ("does not serve as a security boundary"), a secrets file, init scripts and file-access limits (workspace roots by default). Tools include page JavaScript evaluation, file upload and a run-code tool titled "unsafe". Every example uses an unpinned `latest` tag. **Not stated:** a support statement per operating system or architecture, any telemetry policy.
**Official pages (R40, weaker evidence).** `playwright.dev/agent-cli/introduction`: CLI for coding agents (names Claude Code and Copilot), lower token cost than MCP, headless by default, isolated sessions, global npm install. `playwright.dev/mcp/introduction`: lists VS Code, Cursor, Windsurf, Claude Code, Claude Desktop and "any MCP client" — **Antigravity is not mentioned there** — headed by default, persistent sessions by default, higher token cost than the CLI. The summaries were produced by a fetch tool, not copied verbatim, and neither page, as summarised, states a Node version, an operating system, a telemetry policy or a comparison with Playwright Test. They are used only for the publisher's positioning of the three offerings.
**Playwright Test / Library (R35, unchanged).** README: framework with Playwright Test, library, a Cross-Browser table for Linux, macOS and Windows; separate offerings for CLI and MCP in the other two repositories.

## Uncertainties kept as uncertainties
* **Node version.** CLI and MCP say 18; the framework's private root manifest says 20. These are different packages and the difference is **not reconciled**; the MCP record says so, and no install requirement is approved for any of the three.
* **Token efficiency and performance.** The CLI's lower token cost is the publisher's claim (README and official page). It was not benchmarked; the UI says so.
* **"Suggested default".** The publisher's documents position CLI + Skills as the starting point for **coding agents**. That positioning is shown as the publisher's, with the sentence that it does not mean "works in every repository", "installed" or "compatibility verified". It is not enabled, accepted or preselected by anything.
* **Antigravity.** Only the MCP README has an Antigravity section, and it names no surface or operating system, so every Antigravity cell stays `unknown`. A client-configuration note is documentation, not an architecture-specific functional test.
* **Browser state.** CLI sessions (in memory unless persistent) and MCP profiles (persistent by default) differ; sharing one installed tool would not by itself share or isolate a profile. This is recorded as a caution, not resolved.

## How the compatibility labels were chosen
Rule (the same as CATALOG-01): `vendor-declared` only when the publisher's own text names **both** the agent surface **and** the operating system family; no source names a CPU architecture, so `limitation` says so. Anything else is `unknown`. Six cells per entry (Windows x64 / macOS arm64 × `local-cli` / `claude-code-terminal` / `antigravity-ide`), each with its limitation.

The MCP cell for Claude Code rests on a README that documents the command and names OS locations — a judgement call, flagged for the reviewer: it is documentation, not a test.
