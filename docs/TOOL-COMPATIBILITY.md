## Per-Tool Assessment

### 1. Ponytail

- **Purpose/category:** Instruction and plugin bundle that aims to reduce unnecessary implementation and provide code review/audit workflow. It is not a general-purpose binary.
- **Install/update/uninstall:** Claude Code marketplace, Codex/Copilot plugin paths, Gemini extension, `skills` CLI, and other host-specific paths. Source has a dedicated Antigravity **CLI** adapter. A reusable `AGENTS.md`/rules-file path is distinct from a native Antigravity IDE plugin. Update through the host's plugin/extension manager after review. Rollback by removing only the pinned plugin and restoring captured manager-owned rule/hook state; upstream uninstall may leave user state behind. Prefer a reviewed local clone at an immutable commit; never let a tool installer spray files into every detected agent by default.
- **Verification:** Confirm the exact scoped skill/rules/plugin appears in the intended host, invoke a harmless test task, check unrelated agent configs remain byte-identical, and remove the test fixture cleanly. Its benchmark assertions remain upstream claims, not independent proof.
- **Rollback/security:** Host plugin removal plus exact removal of owned hooks/rule files; upstream notes some state may remain. Snapshot `settings.json`, hook files, statusline, mode flag, and repo instructions before setup. Possible overlap: codebase-memory/Graphify hooks compete for context; Caveman can alter prose style; Superpowers overlaps with audit/review workflows.
- **Privacy/license:** MIT. Rules are local; agent outputs still go to configured model provider. Node-based lifecycle hooks expand attack surface.

### 2. codebase-memory-mcp

- **Purpose/category:** Native local MCP server and CLI that indexes code into a persistent SQLite graph and provides structured navigation. Its “token savings” are publisher-reported benchmarks, not guaranteed savings for this user.
- **Platform/dependencies:** `v0.11.0` release artifacts explicitly include macOS ARM64 and Windows x64 (also other platforms); self-contained binary claims no language runtime or API key. Installation may use curl/PowerShell, package managers, or release archive. Exact publisher signing/SLSA evidence is published in release materials; the manager must independently verify it.
- **Agent integration:** Claude Code setup exists. Repository claims a wide agent matrix including Antigravity, but current Google product docs distinguish 2.0, IDE, and CLI. Do not use an adapter until its target path/config and read-only permissions match current Google docs.
- **Validation/rollback:** Check `--version`, MCP JSON-RPC startup with a harmless fixture, index fixture, known graph query, and uninstall after comparing pre/post config. Upstream's recent release describes staged index preservation, shutdown coordination, checksum/signature metadata, and fail-whole indexing; these behaviors still need independent target tests. Update using the install script or selected package manager, not an in-process self-update. Uninstall defaults to keeping indexes. `v0.11.0` changes index format and requires a full reindex; an older binary may not read a newer index. Rollback therefore requires a pre-update index backup or rebuild with the old binary; reinstalling the old executable alone is not a complete rollback.
- **Risk/overlap:** Agent integration writes instructions/hooks/config and background daemon/indexes persist. It may read all project code; configure ignore/exclusion and allowed root. Strong overlap with Graphify; test them separately before offering both.

### 3. Graphify

- **Purpose/category:** Python CLI and agent skill that builds a local AST graph; semantic extraction of non-code material can call the model/API configured for the host.
- **Install/dependencies:** Official package is PyPI `graphifyy`; CLI is `graphify`. Python 3.10+; isolated `uv tool` is recommended. Release/readme supports uv/winget instructions but does not provide a complete architecture release matrix. Installation can install skills, hooks, instructions, and project/global files.
- **Agent integration:** Explicit Claude Code, Gemini CLI, and Antigravity install commands exist in upstream docs. Google’s official plugin/MCP docs confirm the host surfaces exist; an actual Antigravity IDE install-and-query test is still required. Gemini CLI support alone does not satisfy the IDE target.
- **Validation/rollback:** Validate `graphify --version`; run code-only extraction on synthetic repo with network denied and compare known definitions/edges; separately verify docs/media extraction with model calls disabled or explicit consent; query and then uninstall. Update the isolated package to a reviewed pin and refresh host skills only after diff review. Uninstall the host integration; preserve generated indexes unless the user selected deletion. Reinstall the prior package pin and regenerate/reuse a compatible graph backup if schemas differ. Do not commit absolute-path caches/interpreter sidecars.
- **Privacy/risk:** Code AST parsing is declared local; docs/PDF/images use host model or configured provider; optional query logging can include question and corpus path. Turn off query logs by default for manager-driven runs. Overlap with codebase-memory-mcp and MarkItDown.

### 4. Gitleaks

- **Purpose/category:** Go-based local/CI secrets scanner for Git history, directories/files, and stdin.
- **Platform/dependencies:** `v8.30.1` release publishes explicit `darwin_arm64` and `windows_x64` archives and checksums. Homebrew, Docker, Go, and binary paths documented. New features are frozen; README says future releases are security patches only.
- **Agent integration:** No agent-specific requirement; catalog should expose as a user-approved CLI/check rather than silently add hooks or run on every project.
- **Validation/rollback:** `gitleaks version`; fixed synthetic secret fixture should cause expected finding/exit code; clean fixture should return the documented no-findings exit code. Use redaction and temporary output paths. Update only to an exact reviewed release/package version. Roll back by reinstalling the retained prior release and restoring the prior config snapshot/hash; delete test reports only from the disposable fixture.
- **Security/privacy/overlap:** Findings can print secret values unless redaction is configured. Never forward output to AI or sync. `.gitleaks.toml` allowlists can suppress real findings; surface config provenance. Overlaps Betterleaks; do not run two secret scanners by default.

### 5. MarkItDown

- **Purpose/category:** Python library/CLI to convert documents into Markdown for LLM/text processing, not a desktop app. Upstream explicitly treats end-user apps as out of scope; `markitdown-mcp` is a separate package in project scope.
- **Platform/dependencies:** Python 3.10–3.14. Optional format extras (PDF, DOCX, audio, etc.) create different dependency surfaces; do not install `[all]` by default. CI includes Windows tests but no explicit supported OS/CPU matrix is provided.
- **Agent integration:** No built-in Claude Code or Antigravity install path established. Use only after a specific CLI or separate MCP adapter is independently tested.
- **Validation/rollback:** Convert fixed local fixtures of each enabled file type and compare expected structure/metadata; disable plugins and network access in the base profile. Update only inside a pinned isolated virtual environment. Roll back by restoring its prior lockfile/environment or deleting and recreating that isolated environment; preserve user-produced converted files.
- **Security/privacy/overlap:** Executes file/URI I/O with caller privileges. For local-only conversion use `convert_local()` or a stream; restrict URI schemes, paths, private/loopback addresses, and plugins. Azure Document Intelligence/Content Understanding, LLM image description, audio/YouTube integrations can send data externally and incur charges. Overlaps Graphify's document conversion/extraction.

### 6. Caveman

- **Purpose/category:** The Caveman response voice is an agent instruction/plugin. Separate capabilities include a request/output proxy, compression, web browsing, MCP shrink middleware, usage history, and telemetry. Treat each as an independently consented capability.
- **Platform/dependencies:** `v3.2.0`; install scripts for macOS/Linux and Windows PowerShell 5.1+. CLI/proxy requires Node 22.13+; hooks may require Node on the non-interactive PATH. Antigravity CLI has a documented plugin installer; Antigravity IDE and Antigravity 2.0 are separate product integrations/soft probes.
- **Verification/update/rollback:** For profile only, inspect installed instructions and ask a fixture question in the target host; compare untouched payloads. For proxy, a separate local A/B fixture must include recovery identity and provider route checks. The upstream installer's dry-run is useful but not functional evidence. Pin release/tag and check its integrity; same-tag checksum manifests do not protect against moved tags. Update plugins/hooks and CLI/runtime as separate components. Disable proxy routing before removing its CLI. Uninstall agent hooks/integration first; restore prior settings from the ownership journal/manager snapshot; then separately inspect local data stores and remove only with user approval. Uninstall alone does not guarantee deletion of local databases, backups, reports, or credentials.
- **Privacy/risk/overlap:** CLI telemetry defaults on after disclosure and sends content-free events that include IP/install/session/token aggregate metadata; explicitly opt out as product policy requires, and verify the setting reaches background hooks. Proxy traffic processes user prompts/tool results; exact originals/recovery data may persist locally. No proxy, telemetry, history scans, compression, or cloud use as a side effect of choosing the response profile. Overlaps other concise-writing profiles.

### 7. Cloudflare security-audit-skill

- **Purpose/category:** Agent procedure for reconnaissance, coverage-led hunting, fresh candidate verification, structured findings, independent record checking, and reports. It is not a scanner binary.
- **Dependencies/platform:** Markdown plus Node.js validators; requires a coding agent capable of tool use/delegation and an OS-enforced sandbox with networking disabled, allowlisted empty environment, resource limits, and write isolation. If the host cannot provide these, its own workflow says to leave execution as `needs_validation`; do not improvise with an unsandboxed shell.
- **Agent support/install:** Skills CLI (`npx skills add ...`) documented, but no exhaustive vendor/OS compatibility matrix. Exact Antigravity/Claude integration must be verified separately.
- **Verification/rollback:** Validate schema validators on malicious/safe fixtures without executing target code; confirm validators reject malformed ledger/findings. Pin source commit and update only after reviewing its diff. Roll back to the prior pinned skill commit; uninstall only skill files the manager added. Preserve locally generated audit artifacts unless separately requested for deletion.
- **Risk/overlap:** Reports and audit artifacts can expose source paths/findings; keep local unless user previews sanitized export. It is not proof of complete security, and its subagent-based workflow consumes model context. Overlaps Superpowers' review workflow but has stronger coverage/evidence controls.

### 8. Superpowers

- **Purpose/category:** Collection of skills/plugin components for brainstorming, plans, TDD, review, and multi-agent development methodology.
- **Agent support:** `v7.0.0` documents an Anthropic official Claude plugin marketplace and `agy plugin install` for Antigravity CLI. Current Antigravity 2.0 supports plugin marketplace/custom plugin surfaces, and upstream includes `.antigravity-plugin/plugin.json`; still validate target-specific IDE install, approval, and loaded component inventory. The install instructions do not mean every host has identical behavior.
- **Dependencies/update/rollback:** Host plugin runtime and permission/trust model. Updates are host-specific; pin release and inspect diff before applying. Roll back through the host manager to a prior pinned release where supported; otherwise remove the plugin and restore captured manager-owned files. Preserve non-plugin project files. Hooks/subagent code runs with host privileges.
- **Validation/privacy/license:** Test skill discovery, one brainstorm-to-plan workflow, and verify no implementation occurs before approval in a disposable project. MIT. Optional visual companion loads an external logo/version asset; disable unless accepted. Claims of better engineering outcomes remain publisher/evaluation evidence, not guarantee.

### 9. Betterleaks

- **Purpose/category:** Go-based secrets scanner. Stable `v1.9.0` is the latest stable release at snapshot; `v2.0.0-rc.2` is an immutable pre-release. v2 changes CLI flags, report schemas, config loading, SDK, and default provider behavior.
- **Platform/dependencies:** Upstream says portable on modern OS/architectures and documents Homebrew, Go, and containers; fetch exact release assets/checksums to confirm required macOS ARM64/Windows x64 build before any install. V2 source/SDK requires Go 1.25+; users of prebuilt binaries need not install Go.
- **Agent integration:** No upstream Claude/Antigravity agent integration contract established. Provide as explicit CLI scanner only; do not introduce secret validation as an implicit agent hook.
- **Validation/rollback:** `betterleaks version`; validate a dummy fixture with redacted output; `config check` for a custom config; verify findings and summary schema per pinned version. `-v/--validate`, `-a/--analyze`, and `revoke` can call external credential providers or revoke credentials; do not automate. Pin stable v1 by default; quarantine v2 RC until upgrade compatibility and schema are tested. Update with a version-pinned package or release artifact. Roll back to exact v1 package/asset and restore config/report consumer version; v2 config/report migrations are not assumed reversible.
- **Risk/overlap:** The current main README and release lanes distinguish v2 development/RC from stable package-manager v1. Do not use `main`, `latest`, Homebrew `@latest`, Docker `latest`, or the `v2` floating tag as a v2 pin. Overlaps Gitleaks; different rules may have different coverage/false-positive tradeoffs, not a simple drop-in replacement.

## Cross-Catalog Conflicts

- **Code navigation/token reduction:** codebase-memory-mcp and Graphify duplicate indexes/context hints. Evaluate measured context reduction, index size, refresh correctness, and no-network code-only behavior per repo before selecting one.
- **Secret detection:** Gitleaks and Betterleaks overlap but have different rule/config/report behavior. Choose one initially and keep output redacted.
- **Response behavior:** Caveman's profile, Ponytail response text, and existing project/global instructions can conflict. Enforce one manager-selected profile and require review of pre-existing style tools before activation.
- **Audit/review:** Cloudflare security-audit-skill and Superpowers can both delegate or add hooks. Audit tool permissions, token overhead, and output paths; do not enable both hooks blindly.
- **Document ingestion:** MarkItDown and Graphify overlap. Keep cloud converters optional and distinguish format conversion from AI semantic extraction.

## Required Catalog Evidence Record

For every tool/version: exact owner/repo and immutable commit; release/tag; artifact URL and SHA-256; signature/provenance issuer and verified result; license and included third-party licenses; platform/architecture and exact agent surface; dependency lock/runtime; files/registry keys/hooks it will write; process/privilege/network behavior; telemetry; uninstall and data-retention actions; independent synthetic test ID and result; rollback result; research date; unresolved facts. Missing fields remain `unknown`, not implied compatible.
